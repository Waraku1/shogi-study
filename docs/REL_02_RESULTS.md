## Requirement versus assurance

Primary references checked: [GPLv3 §0/1/6](https://www.gnu.org/licenses/gpl-3.0.html), [FSF source delivery FAQ](https://www.gnu.org/licenses/gpl-faq.html#SourceAndBinaryOnDifferentSites), [source corresponding to the conveyed version](https://www.gnu.org/licenses/gpl-faq.html#DistributeExtendedBinary). Corresponding Source is the **preferred form for modifications**, including needed build/install/run scripts and specifically required linked code. §1 excludes qualifying System Libraries and unmodified general-purpose tools/free programs not part of the work; it does not automatically exclude runtime snippets/libraries merely because a compiler produced them. §6(d) requires equivalent source access and clear directions/continued availability for a designated download, not necessarily the same physical server. A private local review packet is not publication.

**Independent rebuilding and byte-identical hashes are not automatic GPL conditions.** Source must correspond to the actual conveyed version and support generating/modifying it. Functional rebuilding is useful evidence; matching hashes are additional assurance. Neither a hash match nor a public Git/npm link alone proves source completeness. MIT itself requires notices, not mandatory preferred-source publication; the included permissive-library sources are a conservative set under the proposed whole-application GPL strategy. Whether components form a combined covered work or independent aggregation remains an owner/legal assessment. These are bounded technical findings, not legal approval.
